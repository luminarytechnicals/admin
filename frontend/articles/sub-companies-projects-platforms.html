Sub-companies, Projects, and Platforms: Understanding the Luminary Technicals Ecosystem

Learn the difference between Luminary Technicals sub-companies, projects, digital platforms, and associated entities, with examples and navigation guidance.

By Luminary Technicals✦23 Feb 2025✦Digital Ecosystem

A clear guide to finding the right place in the ecosystem, from venture profiles and project overviews to the official external websites.

Why distinguish the different parts?

A broad technology ecosystem can contain organizational functions, ventures, individual projects, and public-facing websites. These categories are related, but they answer different questions: who performs a function, which venture a visitor is learning about, what a project is intended to do, and where a service can actually be accessed.

Luminary Technicals uses separate directory and profile pages so visitors can understand a venture before leaving the main site for its own platform.

Sub-company profiles explain the venture

A sub-company profile should describe the venture's purpose, areas of focus, and relationship to the wider ecosystem. It should then provide a clearly labelled button to that venture's official website. This keeps the main site useful as an overview and makes the external destination explicit.

Examples in the ecosystem include James Web Networking, Luminary Webs, and Luminary Books. Their individual profiles on the Luminary Technicals site provide context; the official websites remain the destinations for current services and offerings.

  • Profile page: context, purpose, and relationships
  • Official website: the venture's own live destination
  • Directory: a consistent way to discover all listed ventures

Projects have their own goals

A project is a more focused initiative or product. For example, Luminary Wishes is a digital celebration and personalized-wishes platform associated with Luminary Webs. Its project profile explains its purpose and links to the live platform.

AgroScan and JSET have their own project-overview pages as well. A project page should focus on that project's goals and state, rather than presenting the entire organization again.

Platforms are where people interact

A platform is the user-facing destination where a visitor reads, creates, explores, or uses a service. It may have its own domain and interface while remaining connected to a broader organizational ecosystem.

When a directory contains an external link, the label should make that clear. Visitors should not be sent away unexpectedly when they are expecting to read an internal profile.

Associated entities have a distinct position

Not every related entity is one of the five core organs or a project. Luminary Trust is presented as a directly associated entity with its own profile, distinct from the core-organ structure. A clear page should describe that relationship accurately rather than forcing every name into the same category.

A simple path for visitors

Start with the organization overview for the big picture, open a sub-company profile to understand a venture, read a project page to learn about a specific initiative, and use the official website button when you are ready to visit the live service. This consistent path improves clarity across desktop and mobile navigation.
